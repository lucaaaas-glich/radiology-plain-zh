# 实验怎样避免得出过头的结论

本项目研究的是“能否让一个小模型学会更接近教师的中文报告解释方式”。它没有把一套模型验证成临床产品。

## 实验边界

基础模型是 Qwen2.5-1.5B-Instruct，教师是冻结的 Qwen2.5-7B-Instruct。前者已经具备通用中英文能力；后者只生成中文训练参考，并不参加学生的参数更新。没有训练影像模型，也没有从零预训练大语言模型。

训练数据以英文报告为输入。中文报告输入属于额外的探索性测试，不能用英文测试集的结果替代它。

## 划分和选择

标准化报告文本后做精确去重，并移除与全部官方 validation 报告文本重复的训练记录。使用固定随机种子选取4,096条训练记录，以及各256条开发、测试记录。开发和测试来自官方 validation 的不相交部分；官方 test 没有用于最终指标。

文本不重复仍然可能有同一患者的不同检查、近似模板或同义报告。原始数据没有可供本实验使用的患者 ID，因此没有患者级独立性保证。最终指标只对应这个子集，不能直接比较别人的官方榜单。

只按开发集答案 token 的交叉熵选择两轮训练中的 checkpoint。最终测试结果不能用于这次实验的学习率、轮数或提示词选择。后续若根据失败样例改进，必须明确标成下一轮探索，并建立新的最终留出集。

## 合成标签的偏差

教师使用专业原文及英文通俗参考生成中文。它可能保留难懂术语、漏掉细节，或把英文参考中的误解带入中文。`teacher_accepted` 只代表中文比例、最短长度与正常结束检查通过。

至少12个字符的过滤会排除部分正确但很短的答案。此规则在训练开始前固定；筛选数量保存在结果中，不应把被筛掉的短句全部称为错误。测试成员保持不变，文字相似度只在有合格参考的成员上计算，基线和微调版本使用完全相同的成员。

教师与学生属于同一模型家族，参考本身又由教师生成。ROUGE或chrF提高最直接表示“更接近教师文本”，不能单独证明更准确、更通俗或更安全。

## 个案检查

20条合成挑战输入和逐条事实清单在模型对比之前编写，见 `examples/challenge.jsonl` 与 `examples/challenge_rubric.json`。其中14条英文、6条中文。清单检查否定、左右侧、数字、变化、不确定性、原有建议及嵌入式指令。

逐项比较实际输出，分开记录事实变化和难懂术语。AI参与的文本检查没有医生审核的效力；20条样例也不足以给出可靠的“医疗准确率”。完整输出留在本地，避免只展示最漂亮的例子。

另外从最终测试报告中按原文关键词选择5类观察病例。选择不使用模型分数，也不按微调效果好坏挑选。全文和逐例分析保留在本地结果文件中；仓库仅提交汇总、来源ID和分析。

## 运行和复现

记录模型、数据 revision、环境包版本、配置、训练历史、开发集选择依据、推理设置、计时和显存。单个训练种子不能证明结果在重复训练中稳定。配对bootstrap区间仅描述当前测试报告与合成参考上的词汇指标变化。

学校A100上使用BF16权重，本地Mac使用合并后4位量化模型。量化会改变数值，必须单独运行挑战集；不能把A100速度当成本地速度。GPU统计使用批量生成，而本地交互逐条生成，两者也不是同一种吞吐量测量。
