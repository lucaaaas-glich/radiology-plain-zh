# V3：真实长报告事实清单流程

本计划在生成、查看任何 V3 新测试预测前写定。目标是在约五小时研究窗口中检验事实清单是否有用，不承诺模型达到临床使用水平。

## 数据和防止泄漏

- 开发只使用已公开检查过的 V2 开发及最终报告、已有错误，以及针对程序契约的单元测试。V2 的旧最终报告从本轮起属于开发材料。
- 新最终测试取固定版本 BioLaySumm2025-LaymanRRG validation 中 40 份 1000–4000 字符英文原报告：28 份 1000–1499、8 份 1500–1999、4 份 2000–4000 字符。这里的“长”是相对该数据集，不代表所有临床长文书。
- 排除 V1 全部训练/验证/测试原文及 V2 开发/测试的标准化重复，再排除词语五元组 Jaccard 相似度至少 0.8 的近重复。数据没有可验证的患者身份，不能声称患者级独立。
- 抽样种子、原数据和输入 SHA256、全部匿名 ID 先写入 examples/v3/real_manifest.json 并提交；原文与模型原始输出不重新公开分发。
- 最终候选及所有推理文件、模型权重清单、生成参数在新测试生成前另行冻结。最终结果只用于评估，不能再改模型后继续宣称同一批是未见测试。

## 两个实际生成方案

1. V2：原先选定的 Qwen3.5-27B NF4、逐句生成与复核方案，使用原始 dev6 冻结代码，不用结果更差的事后重检查版。
2. V3：同一模型和量化，用章节及上下文、带原文依据的事实清单、中文生成、对照原文检查新增/遗漏。程序保留清单、生成尝试、复核和原文；复核仍会出错。

每份报告按固定顺序运行两个方案，不挑选最好的一次输出；失败保留为失败。记录调用次数、输入/输出 token、加载和推理时间、GPU 内存。算力不同不得隐去。

为区分“事实提取”与其他流程修改，预先增加一个小规模对照：在相同新测试顺序第 1、5、9、13、17、21、25、29、33、37 例上，运行相同 V3 代码但 `use_ledger=False`，跳过清单提取，保留原文、分组生成、相同复核与最多一次重试。该 10 例是机制探索，不代替 40 例主要对比；结果不用于重新选择最终候选。V2/V3 总体还存在上下文、分段、词典等差异，不能把所有收益都归因于清单。

## 主要评价：完整报告逐例人工式审阅

由本项目 AI 阅读原文、最终展示文字及保留原文的位置，逐例记录；这不是独立、盲法或临床医生评价。两臂用同一标准，review 绑定输入与最终输出 SHA。

- **明确事实错误报告数**：任何临床事实被新增、改反、错配，或重要事实被悄悄遗漏。限定词、否定范围、可能性、检查目的与真正建议混淆均检查。主动显示“该部分未完成”属于不完整，不当作隐蔽遗漏，但其他已展示文字仍可能有错。
- **完整且未发现事实错误的报告数**：所有重要原文内容均得到忠实中文解释；没有必要的原文回退，且没有严重含混的词义。纯章节标题或未定义的排版缩写可原样保留，但不得由此隐去难以解释的临床内容。
- **未发现明确错误但不完整、以及精度/含混问题**另列。每臂都同时报告错误与完整覆盖，拒绝变多不能算能力提升。
- **完全生成率与片段覆盖**为实现指标；V3 分段不同，所以不同方案的片段比例不能直接当临床效果比较。报告级完整忠实是主要对比。对纯结构标记的保留与临床句子的回退分开记录。
- **中文可读性**：通俗为主、通俗与术语混合、专业或难懂；有词典不等于患者已经理解。没有真实患者测试。
- 在 V3 清单本身记录明显遗漏或误提取是否传到最终输出；检查最终输出必须回到原报告，不能只对清单打分。
- 清单详细审阅预先固定为新测试顺序第 1、5、9、13、17、21、25、29、33、37 例，另外检查最终出现错误的个案以分析原因；未审清单不标作“正确”。所有 40 例的最终中文两臂都要逐例审阅。
- 临床内容完整性与机械的“所有片段生成”分开判断：若只剩纯排版或未定义标记原样保留，仍可判临床内容完整；如果保留的是未解释的临床句子，则不完整。这一解释同样适用于 V2 和 V3。明确错误、不完整无明确错误、完整但表达精度有疑问、完整忠实四类分别统计。
- 配对记录旧错误消失/新增、完整忠实改善/退化；不给小样本自动规则分数冠以“医学准确率”，不以文字相似度替代事实评价。
