# V3 复现与使用

本页说明独立 V3 入口。旧版启动文件、权重、锁文件和结果保持原样；学校 27B 与本机 4B 是不同实验，不能共享同一组效果数字。

## 先看哪些文件

- `examples/v3/real_manifest.json`：最初冻结的 40 份真实长报告候选池。
- `examples/v3/main20_manifest.json`、`docs/v3/测试规模修订.md`：在任何新预测之前固定的 20 份主测试，以及仍保持原样的 10 份去清单对照。
- `examples/v3/final_candidate.lock.json`：最终选择完成后生成，记录模型、代码、请求、开发证据及输入散列。没有此文件就还没有冻结最终候选。
- `docs/v3/预注册评估方案.md`、`docs/v3/开发取舍.md`：评价标准、失败和取舍。新增修订文档优先于原方案的 40 份主测试数量，原方案不覆盖。

## 本机运行一个新报告

在项目根目录，把需要解释的报告保存为 UTF-8 文本，例如 `data/v3/my_report.txt`。使用已经存在的本机模型，不会自动下载：

```bash
.venv-mac/bin/python -m radplain.predict_v3 \
  --backend mlx \
  --model artifacts/v2/qwen35-4b \
  --input data/v3/my_report.txt \
  --html data/v3/my_report.html \
  --json-out data/v3/my_report.json
```

页面可以展开对应原文及可用的事实清单，未通过核对的片段明确保留原文。清单仅是模型整理的阅读辅助，原文摘录真实不等于理解正确。公共 JSON 不包含被拒绝的中文草稿；研究实验另行保存完整过程。

该命令使用本机 4B 模型，学校 27B 的结果不代表它的表现。它也不是自动诊断或治疗工具。模型目录必须已经存在，输出文件存在时拒绝覆盖。默认 V2 启动器没有被悄悄换成 V3。

## 学校重跑时的隔离方式

V3 单独目录接收不可变请求；一次 Slurm 分配只加载一个模型。先检查账户已有作业，再提交新工作。学校当前每账户只允许一个并行作业，不通过别的账户或配额绕过限制。

原模型为 `Qwen/Qwen3.5-27B`，revision `fc05daec18b0a78c049392ed2e771dde82bdf654`，NF4 双重量化、BF16 计算、不采样、关闭思考输出。下载后必须验证原 V2 锁文件中的所有权重散列。旧 V2 对照从 `artifacts/v2/gpu-reference-dev6` 恢复，不能用当前开发目录中后来修改过的 V2 代替。

FLA 安装在 V3 的独立依赖目录，只把上游两个 Gated Delta Rule 运算切换为固定版本的实现。最终两种方案共享该运行方式；这不是模型权重微调。运行时通过 `RADZH_V3_ACCEL_PATH` 指定独立目录，其版本及 wheel 散列见 `examples/v3/fla_package_sources.json`。不修改另一个作业的环境。

`scripts/freeze_v3.py` 将已经完整审阅的旧例候选打包，并检查请求、源数据和代码散列；冻结文件提交后才能把 `.json.pending` 请求原子改名为 `.json` 交给 worker。新报告的输出只用于评分，不能修改模型后再把同一批称作未见测试。

```bash
python -m scripts.summarize_v3 \
  --outputs results/v3/real-data/final/v3/outputs.jsonl \
  --review results/v3/final/v3_review.json \
  --stage final \
  --out results/v3/final/v3_summary.json
```

评分脚本要求预先固定的全部 ID、原文指纹和每份输出的审阅散列一致；缺例、换原文或审阅后修改输出都会报错。`--stage ablation` 对应原池第 1、5、9、……、37 份。真实原文和完整预测保留在忽略目录，GitHub 仅保存代码、固定名单、运行数字、审阅问题摘要和散列。

## 理解比较范围

V2 与 V3 除了事实清单，还存在分段、上下文、词义辅助和复核策略差异。20 份主测试比较的是整个流程；10 份去清单对照只能初步探索清单的作用。中文内容都由项目 AI 对照原文检查，既不是独立盲评，也没有临床医生或真实病人参与。规则放行率、全部生成率、文字相似度都不能称作医学准确率。
