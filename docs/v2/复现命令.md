# V2：运行与复现

这些命令从本项目根目录执行。学校与Mac环境分别保留；不要在另一个作业目录安装依赖，也不要覆盖已有结果。最终结果以候选锁和逐例复核为准，开发目录不能替代最终测试。

## 已准备好的这台Mac

双击`开始解释报告_V2.command`。粘贴完整报告，用空行结束；输入`q`退出。程序显示加载和逐句进度，并把解释存为本地网页。网页中的“查看对应原文”可展开对照，未完成的片段会保留原文，术语说明附来源。

单次命令：

```bash
.venv-mac/bin/python -m radplain.predict_v2 --input examples/英文报告.txt --html-dir data/v2/explanations --open-html
```

程序从`configs/v2_local.json`读取选定模型。此配置与候选锁已提交；缺少它时应检查克隆版本。第一版启动器和权重继续保留。

## 在另一台Apple Silicon Mac准备4B模型

先克隆自己的项目，再创建独立环境。模型约3GB，此外还要为环境、系统运行和交换空间留出余量；“8GB内存可加载”不等于多任务下总能流畅运行。

```bash
python3 -m venv .venv-mac
.venv-mac/bin/python -m pip install -r requirements-v2-mac.txt
.venv-mac/bin/python scripts/prepare_v2_local_model.py
.venv-mac/bin/python scripts/prepare_v2_local_model.py --verify-only
```

恢复工具只下载锁文件中记录的revision与文件，逐一核对SHA256，不修改实验记录。已有文件不同则拒绝覆盖；在新的克隆中处理，保留原来的文件。模型属于MLX Community的公开量化转换，不是本项目自行训练的4B权重。首次下载需要网络；下载后本机推理脚本不把输入发送到外部服务。

第一版1.5B是本项目LoRA训练后导出的权重；恢复4B命令不会生成它。独立复现V1需按根目录README的训练与导出流程。这里没有提供一个“下载4B就复现全部实验”的快捷承诺。

## 冻结后的本机最终比较

最终候选锁包含三臂：V1直接改写、4B直接改写、4B逐句与核对。运行器要求锁、代码和解除查看限制记录已提交，且模型文件与输入SHA一致。先前输出目录存在时拒绝覆盖。

例如，运行已冻结的逐句合成测试：

```bash
PYTHONPATH=. .venv-mac/bin/python scripts/run_v2_pipeline.py --model artifacts/v2/qwen35-4b --out results/v2/reproduction_local_evidence --split holdout --mode evidence-critic --max-tokens 384 --candidate-lock examples/v2/candidate_local.lock.json --arm local_evidence
```

真实报告使用`--split real-holdout`，输出必须位于被Git忽略的`results/v2/real-data`。真实数据不随仓库分发，需要按`real_manifest.json`的来源、revision、划分和散列恢复。不能用新版本数据悄悄替代旧输入。

## 学校27B参考与重新筛选

原27B运行使用A100 40GB、NF4双重量化及BF16计算。公开BF16权重下载约55.6GB，应放入学校分配的scratch；当前Mac没有这些权重。原实验的代码版本与本机最终版本不同。

```bash
python3 scripts/restore_v2_gpu_reference.py
```

该命令只恢复并核对原GPU代码，不申请GPU、不下载权重。模型修订、21个源文件散列与生成设置见`candidate_gpu.lock.json`。实际评估入口为恢复快照的`run_v2_remote_holdout.py`；普通`--backend cuda`不代表NF4，不能用它冒充原实验。Slurm脚本包含原学校路径和账户配置，迁移机器时需要在独立快照中适配，不能声称适配后逐位相同。

额外的重新筛选臂使用`scripts/recheck_v2_outputs.py`。它需要原始输出、原始runtime、同一报告序列和冻结的重新筛选锁。只重新检查已经生成的候选，复用旧语义判定和旧词典，模型调用为零；仍保留原GPU推理耗时。不要把它称为重新训练或新的模型核对。

## 重新汇总与检查

`scripts/summarize_v2.py`先验证每条输出与复核记录的散列。没有完整复核时只能生成空模板，不能自动猜测事实正确。`compare_v2_reviews.py`比较同一份报告的新增错误、消失的错误及完整解释变化；`plot_v2_outcomes.py`分别显示错误、忠实、未完成和精度顾虑。

真实原文和全部候选只保存在忽略目录。GitHub中的真实报告复核使用ID、散列与概括后的问题描述；合成测试可以完整公开。浏览器网页隐藏失败候选，研究JSON可能保存它们，两者用途不同。

## 版本标签的已知限制

本次冻结的本机流程在开发记录中称dev8，但输出里的`version`字段沿用了`evidence-zh-v2-dev7`标签。不要用这个短标签判断源代码版本；以`candidate_local.lock.json`、runtime的源文件SHA和候选提交为准。发现这项元数据命名问题后没有修改已冻结的代码或重写预测。
