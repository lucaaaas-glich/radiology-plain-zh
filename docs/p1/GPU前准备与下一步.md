# 数据质量改进：GPU 前准备与下一步

日期：2026-11-16（布里斯班）。本轮按用户要求停在 GPU 实跑之前。

现在已经能把数据送进一条独立的新训练流程，但还没有训练出新模型，也没有证明效果提升。旧 V1/V2/V3 代码、权重和评估保留；工作位于 `feat/data-quality-p0`。本轮没有连接学校、查询/提交 Slurm 作业、运行模型或恢复自动任务。

## 做完了什么

1. **确认原始基座。** 恢复固定版本 Qwen2.5-1.5B-Instruct，9 个文件逐个核对上游 Git/LFS 散列，权重约 3.09 GB。它是未合并旧 LoRA 的原始模型。只下载及计算散列，没有加载模型。
2. **隔离相似报告。** 汇总旧项目使用记录，按完全相同、5 词片段 Jaccard ≥ 0.8、保留否定词的短数字模板分组。旧训练与开发集有一个模板组相交，涉及 5 条训练样本；这些样本从新候选排除，不改写旧评估结论。这是文本相似，不等同同一患者。
3. **检验筛选规则。** 先固定 60 对人为设计的正确/改错句子，再开发及验证规则。规则检查数值、日期、左右、否定、不确定性等词面信号。不同模板的 20 对验证题中，抓到 18 个已知改动，20 个正确对照未误报；这些是 AI 编写的小型诊断题，不是医学准确率。
4. **检查真实训练答案。** 对旧训练集 4,096 条运行筛查：4,066 条格式合格，其中 686 条有风险标记、3,380 条未标记。另在看答案前固定 18 条抽查，逐条比对原文。抽查是项目 AI 审阅，人工/独立临床审阅仍为 0。
5. **准备可比较的数据。** S0/S1 各 1,024 条，来源、报告长度、数字、否定、不确定性、时间信息、答案长度的联合分层数量一致，共用 40 条开发数据。先导实验单独取 96 条训练、32 条验证。
6. **用真实分词器做 CPU 预检。** 所有候选样本都通过，没有截断或超长淘汰；提示词和填充不计入训练损失，只学习答案及结束标记。训练脚本、Slurm 模板、输入/输出保护及回归测试已经准备，61 项相关 CPU 测试通过。强化输入哈希和路径保护后重放数据准备，6 份训练/验证文件逐字节一致。下载断点续传只做了模拟回归验证，尚未测试真实网络中断恢复。

## 为什么不能直接把“未标记”叫作“高质量”

真实抽查暴露了简单规则的局限：正确翻译的月份也可能被报成数字错误；“报告说放了导管”被扩写成“导管位置正常”，却可能完全不触发规则。另有前后方向反转、把影像征象改成感染诊断、遗漏器械尖端等问题。

18 条抽查包括有标记 6 条、无标记 6 条、其余格式合格池随机 6 条。前两组都观察到 3 条明确的源文一致性错误。这说明标记不能单独充当答案质量判定；样本很小且有意分层，不能把这些比例当作整个训练池的错误率。信息缺失、明确错误、不可判分别计数；技术采集信息遗漏也记为缺失，但没有声称医生会认定它必不可少。公开记录只保存散列和匿名问题摘要。18 条中，明确源文一致性错误、信息缺失、存在不可判部分分别为 8、12、8 条，三项允许重叠；这些数量也不是整池质量估计。

因此，**本轮没有通过正式训练的答案质量验收**。保留筛查失败和候选数据，未根据这批抽查重新调规则，更没有把 AI 判断伪装成人工金标准。后续应在开发材料上完善语义核对与日期等值识别，再用新保留材料验证筛选是否可靠。

## 两组候选究竟如何比较

| 项目 | S0：共同可选范围内分层随机 | S1：同层未标记候选 |
|---|---:|---:|
| 训练报告 / 独立文本组 | 1,024 / 1,024 | 1,024 / 1,024 |
| 有规则风险标记的报告 | 165 | 0 |
| 同一开发集 | 40 | 40 |
| 单轮完整输入 token | 244,814 | 243,891 |
| 单轮答案及 EOS token | 46,437 | 45,968 |
| 预定两轮优化步数（未执行） | 128 | 128 |
| 超长淘汰 | 0 | 0 |

直接筛掉全部风险样本，会使时间信息占比从 32.93% 降到 24.08%。本轮匹配上述特征，避免把“任务变简单”误当作模型能力变强。S0 也受到 S1 可选数量限制：9 个没有未标记候选的分层、合计 9 条原始候选，不能进入任何一组。它不是从全部训练池无条件随机抽样。

两组有 859 条相同，占 83.9%，实际只替换 165 条。答案 token 总量仍差约 1.01%，输入 token 差约 0.38%，不能称为严格等 token 预算。疾病种类、事实数量等未完全匹配；单次小规模比较即使有差异，也不能都归因于筛选质量。此次只准备数据，不作模型效果结论。

## 新的真实长报告够不够

在已注册的历史报告、预留报告、近重复/模板组和可能的片段母报告之外，官方验证文件还剩 6,841 个不同文本，分属 6,805 个文本组。归一化字符长度在 1,000–1,499、1,500–1,999、2,000–4,000 的可用组分别为 37、14、3。

这意味着不能照搬旧版最后一档要 4 份的抽样配额。本轮只检查可用数量，没有选择或阅读新最终测试预测。未来必须先重新固定合理配额和评价标准，再生成结果。文本分组可能误排或漏排，患者独立性、基础模型预训练是否见过报告仍未知；历史暴露清单也保留了 1 条用途不明确的文本，未将其放回新测试池。

## 下一步为什么需要 GPU

最先需要实跑的是 **96 条训练 + 32 条验证，1 轮、6 个优化步骤** 的工程先导。它回答的是：原始模型能否加载、LoRA 能否更新、损失和梯度是否有限、保存的权重是否有效、显存及耗时是多少。它不回答医学效果是否提高。

当前训练实现采用 LoRA：冻结原始大部分参数，只训练注意力投影上的小矩阵；使用原始模型生成答案的交叉熵作为目标。只有答案和 EOS 参与损失，提示词与 padding 被屏蔽。每 4 个大小为 4 的小批次累积一次梯度，得到 16 条有效批次，按有效答案 token 加权。开发集损失用于选择 epoch。新两组共用这套实现；它与旧 V1 的批次权重及 EOS 处理有差别，因此不能把和旧 V1 的差值全部算成数据筛选收益。

先导通过后仍需完成答案质量验收、固定新测试及基线方案，再决定正式 S0/S1 比较。当前只保存适配器和开发选择记录，不保存完整优化器/RNG 续训状态；任务中断不能冒充精确恢复。尚未进行 CUDA 加载、前反向、权重重载或生成评估，不能用 CPU 测试代替这些结果。

## 复现入口

以下命令在项目根目录执行。所有输出路径必须是新的；不要覆盖本轮报告。原始数据、权重、完整审阅材料在 Git 忽略目录中，仓库只提交代码、合成诊断题、匿名摘要和散列，因此单独克隆仓库不能自动得到真实数据。

CPU 环境在 `cache/p1-cpu-venv`，依赖见 `requirements-p1-cpu.txt`。它没有 torch。本轮发现既有 Mac 环境的 Transformers API 不同，以及新环境缺少模板依赖 jinja2；已在独立环境解决，没有改旧环境。

```bash
cache/p1-cpu-venv/bin/python -m radplain.train_p1 preflight \
  --mode pilot --config configs/p1_pilot.json \
  --data data/p0/pre-gpu-20261116/prepared/pilot \
  --tokenizer artifacts/p1/base-model \
  --out results/p1/NEW-pilot-preflight
```

完整两组 CPU 记录分别在 `results/p1/pre-gpu-S0-20261116/` 和 `results/p1/pre-gpu-S1-20261116/`；简明汇总在 `results/p1/pre_gpu_summary_20261116.json`。上游锁在 `configs/p1_base_files.lock.json`，原始恢复工具为 `scripts/prepare_p1_base.py`。

GPU 入口为 `scripts/run_p1_pilot_a100.sh`，**本轮未执行**。未来连接学校后先检查现有作业、账号/分区及 A100 分配规则，避免重复提交。在全新项目专属环境中验证学校 CUDA torch 与 `requirements-p1-gpu.txt` 兼容，再设置 `P1_PYTHON`、`P1_DATA`、`P1_MODEL`、全新的 `P1_RUN_NAME`；不得沿用或修改 YOLO 和旧实验环境。模板没有内置 SSH、下载、提交或后续自动实验。

完成这一步后，GPU 的主要价值是检验训练及生成表现；它无法自动把有错的参考答案变成可靠监督。当前最值得补的仍是答案的语义质量。
